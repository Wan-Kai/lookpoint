# lookpoint

macOS 菜单栏工具，只用笔记本自带的摄像头：

1. **看哪块屏，光标就去哪块屏**：根据头部朝向，在内建屏和外接屏之间切换。不做眼动追踪。
2. **用手势代替鼠标**：移动、点击、拖拽、滚动、左右切换空间（同触控板三指横滑），外加右 Alt（切换语音输入）和回车。

画面只在本机内存里处理，不保存、不上传。零第三方依赖。

---

## 快速开始

1. 构建并打开 App（见[构建](#构建)），或者直接打开已经构建好的 `build/DerivedData/Build/Products/Debug/Lookpoint.app`。
2. 第一次运行会请求权限：
   - **摄像头**：必须，点允许。
   - **辅助功能**：手势控制鼠标、按键，以及"打字时暂停"都需要。在菜单里点「授予辅助功能权限…」，然后到 系统设置 → 隐私与安全性 → 辅助功能 里打开 Lookpoint。
3. 菜单栏出现 💻 图标（当前在内建屏）或 🖥 图标（当前在外接屏），点开就是控制面板。

> **找不到菜单栏图标？** 刘海屏上空间不够时，macOS 会把图标藏起来。**再打开一次 Lookpoint.app**，会弹出一个内容相同的「Lookpoint」状态窗口。也可以到 系统设置 → 菜单栏 里确认 Lookpoint 是允许显示的。

### 控制面板

| 项目 | 说明 |
|---|---|
| 按头部朝向切换屏幕 | 总开关，关掉后摄像头也会关闭 |
| 手势控制鼠标 | 打开后，手势真正控制鼠标和键盘 |
| 摄像头 / 头姿 / 当前屏幕 / 手势 / 副屏校准 | 实时状态 |
| 校准副屏… | 见下文 |
| 手部实验… | 看手部识别效果，空跑手势，调参（见下文） |

## 用法一：看哪块屏，光标去哪块屏

不用做任何操作，打开就生效。

- **内建屏**：正对摄像头就算（`|yaw| < 8°`），不需要校准。
- **外接屏**：头转向它，停留约 0.3 秒，光标就跳过去，回到你上次离开这块屏时的位置。
- 只移光标，不点击，所以键盘焦点还在原来的窗口。要在另一块屏上打字，先点一下。

**建议校准一次**（菜单 → 校准副屏… → 开始，倒计时结束后看着外接屏中央，保持约 1.5 秒）：

- 不校准时，头往左或往右转超过 15° 都算看外接屏。
- 校准后只认外接屏所在的方向，外接屏放在上方也能用；看另一边、低头看键盘都不会误切。

**它什么时候不切换**（为了防止误切）：

- 打字、动鼠标之后 1.5 秒内；
- 只是瞟一眼（不到 0.3 秒），或者头停在两块屏之间的过渡区域；
- 检测不到脸的时候（比如头转得太偏）；
- 手势接管鼠标期间、校准窗口或手部实验窗口打开时。

## 用法二：手势控制

在控制面板里打开「手势控制鼠标」。手抬到摄像头前，自然的高度就行（大约在画面中间），手掌朝向屏幕。

### 手势表

| 功能 | 怎么做 |
|---|---|
| **激活** | 张开手掌，保持 0.4 秒 |
| **移动光标** | 张开手掌平移。有加速：快速挥一下就能到屏幕边缘，慢慢移动可以精确定位（见下方"光标加速"） |
| **停住光标** | 换成任何其他手形（比如握拳）。可以握拳把手挪回中间，再张开继续，相当于把鼠标拿起来再放下 |
| **单击** | 拇指和食指捏一下 |
| **双击** | 0.4 秒内捏两下 |
| **拖拽** | 捏住不放，移动手，松开就放下 |
| **上下滚动** | 伸出食指和中指（V），上下移动手，内容跟着手走，像触控板双指滑动 |
| **左右切换应用（空间）** | 伸出食指和中指（V），**快速**左右挥，等同触控板三指左右滑：**向左挥切到右边**的全屏 App / 桌面，向右挥切到左边。只切光标所在的那块屏 |
| **右 Alt** | 只伸食指（指向），**静止**保持 0.6 秒 |
| **回车** | 用右 Alt **结束**说话后，手继续指着不动，再过 0.8 秒 |
| **退出** | 把手放下或移出画面 0.5 秒，或者直接开始打字 |

手势接管期间不会切屏：头决定在哪块屏，手只在这块屏里移动光标。

### 语音输入并发送（以豆包输入法为例）

1. **指向，静止 0.6 秒**：发送右 Alt，豆包开始听。这时可以把手放下说话。
2. 说完后**再指向，静止 0.6 秒**：再发送一次右 Alt，豆包结束录音。
3. **手继续指着不动**，0.8 秒后自动按回车。这 0.8 秒也是在等文字上屏。
   - 只想结束、不想发送：在这 0.8 秒内换个手形或者动一下手就行。

已用豆包输入法实测：按一次右 Alt 出现语音浮条，再按一次浮条消失。其他语音工具只要快捷键是"按一下右 Alt 开始、再按一下结束"，也同样适用。Mac 上的右 Alt 就是右 Option ⌥，键码 61。

> 程序靠数自己发过几次右 Alt，来判断这次是"开始"还是"结束"。如果中途用键盘按过右 Alt，或者语音工具自己停止了录音，计数就会对不上：手部实验窗口里"语音输入"一行显示的状态，和豆包的实际状态不一致。这时再做一次指向保持就能对齐。

### 光标加速

光标走多远，看手移动的距离，也看手有多快。按屏幕宽度计算，所以内建屏和外接屏的手感一样：

| 手的动作（距离按画面高度算） | 光标移动 | 内建屏 / 外接屏 |
|---|---|---|
| 快速一挥，0.3 秒移动 0.25 | 1.67 个屏宽，从任何位置都能到边缘 | 2523 pt / 4272 pt |
| 中速，0.8 秒移动 0.25 | 半个屏宽 | 769 pt / 1302 pt |
| 慢，2 秒移动 0.1 | 0.06 个屏宽 | 90 pt / 153 pt |
| 很慢，1.5 秒移动 0.05 | 0.03 个屏宽 | 45 pt / 76 pt |

用法：先快速挥到目标附近，再慢慢移动对准；手挪到画面边上时，握拳把手收回中间再张开继续（离合）。觉得太快或太慢，调 `GestureStateMachine.Config` 里的 `slowGain` / `fastGain`（每移动 1 个画面高度走几个屏宽，默认 0.6 / 8）和 `slowSpeed` / `fastSpeed`（加速从多快开始、到多快封顶，默认每秒 0.1 / 1.2 个画面高度）。

### 左右切换的细节

- 等同触控板的三指左右滑：切换桌面空间和全屏 App。方向也和触控板一样，内容跟着手走，所以**手往左挥，切到右边那个空间**。
- 实际发送的是系统快捷键 ⌃→ / ⌃←（系统设置 → 键盘 → 键盘快捷键 → 调度中心 →「向左/向右移动一个空间」，默认开启）。
- 两块屏各有自己的空间时（系统默认），只切换光标所在的那块屏，也就是你正看着的那块。
- 每个 V 手势开始时，先看手最初往哪个方向移动：上下就是滚动，左右就是切换，直到手离开 V 都不会变。
- 挥手要快：一笔挥出约 8% 画面高度，峰值速度达到每秒约半个画面高度。慢慢横移不会触发。
- **挥完自然收手就行**：从上一笔终点附近出发、往上一笔起点方向走的那一笔（1.5 秒内）算作收手，不会触发反向切换；在外面停一会儿再收回来也一样。收手之后的下一笔恢复正常判断，所以"左挥、收回、左挥、收回"会连续往同一个方向切换。
- 真想反向切换：先收手回到原位再挥；或者在挥出去的位置停 1.5 秒以上再往回挥。
- 挥得快时画面有拖影，偶尔有几帧认不出手，0.25 秒以内的丢帧不会打断手势。
- 已实测：外接屏上左挥从一个全屏 App 切到右边的下一个，右挥切回来，内建屏不受影响。用 2026-11-10 的挥手录制回放（向左 8 次、向右 7 次，每次都自然收手），15 次全部认对，没有一次把收手当成反向挥手。

### 使用建议

- 光线充足、手完整地出现在画面里时识别最好。
- 先在**手部实验**窗口里空跑练习，熟悉之后再打开「手势控制鼠标」。
- 暂时不想用手势时，直接关掉开关。关掉后不再跑手部识别，也就不占这部分 CPU（接管期间约占一个核心的 25–30%）。

## 手部实验窗口

控制面板 → 手部实验…。窗口打开期间每帧都跑手部识别（30 fps），并暂停按头部朝向切换屏幕。

- **左侧画面**：镜像显示，和照镜子一样。白色是手部骨架；红线和绿线分别是食指尖的原始轨迹和滤波后的轨迹；按下左键时，指尖圆点变成黄色。
- **底部曲线**：捏合比，即拇指尖到食指尖的距离除以掌长，和手离摄像头多远无关。两条虚线分别是按下阈值 0.25 和抬起阈值 0.40。
- **右侧面板**：
  - 「手势接管鼠标和键盘」开关：关着时是**空跑**，状态机照常运行，只显示它会发出什么事件；开着时就真正控制鼠标键盘。
  - 当前手势状态、手形、捏合比、无名指和小指的伸直比、语音输入状态。
  - 点击次数、滚动距离、右 Alt 次数，以及最近的事件日志（包括左挥、右挥）。
  - 检测帧率、识别到手的比例、单帧耗时、手静止时的抖动。
- **测试右 Alt**：不做手势，直接发一次右 Alt，用来检查语音工具有没有反应。
- **开始录制 / 停止录制**：把逐帧手部关键点存到 `~/Documents/lookpoint-recordings/hand-*.json`，可以用来调阈值、写测试。

## 常见问题

| 现象 | 处理 |
|---|---|
| 菜单栏没有图标 | 再打开一次 Lookpoint.app，会弹出状态窗口；或者先切到 Finder（菜单短，图标有地方显示） |
| 摄像头显示"未授权" | 面板里点「打开摄像头权限设置…」，允许 Lookpoint |
| 手势状态一直显示"等待辅助功能权限" | 系统设置 → 隐私与安全性 → 辅助功能，打开 Lookpoint。重新构建后如果失效，先移除再添加一次 |
| 头姿数值乱跳、切屏不准 | 在系统的摄像头视频效果菜单（点菜单栏的绿色摄像头标志）里关掉「人物居中」，它会裁剪画面，干扰头部角度判断 |
| 手势激活不了 | 手抬高一点（不要放在画面最下面的 1/4），五指张开，保持不动 |
| 握拳时偶尔会点一下 | 握拳前手先做出了捏合的样子，这种情况分不出来。直接从张开变成握拳即可 |
| 回车发早了，文字还没上齐 | 调大 `GestureStateMachine.Config.enterDelay`（默认 0.8 秒） |
| 实验窗口显示"左挥/右挥"，但没切换 | 确认系统设置 → 键盘 → 键盘快捷键 → 调度中心里「向左/向右移动一个空间」是开着的；已经在最左或最右的空间时也不会再切 |
| 挥手认不出来 | 挥快一点、幅度大一点；V 刚出现时先别上下动，否则这次 V 会被锁定成滚动 |
| 想反向却没切 | 刚挥完紧接着往回挥会被当成收手。先回到原位再挥，或者停 1.5 秒以上 |

## 构建

要求：macOS 14+，Xcode 26（Swift 6）。

```sh
open Lookpoint.xcodeproj            # ⌘R 运行
# 或命令行：
xcodebuild -scheme Lookpoint -derivedDataPath build/DerivedData build
open build/DerivedData/Build/Products/Debug/Lookpoint.app
xcodebuild -scheme Lookpoint -derivedDataPath build/DerivedData test
```

调试构建支持两个启动参数，用来检查按键能不能被目标程序接收：

```sh
# 启动 3 秒后发一次右 Alt
open build/DerivedData/Build/Products/Debug/Lookpoint.app --args -debugRightAltAfter 3
# 启动 3 秒后发一次 V 左挥（⌃→，切到右边的空间）；-debugSwipeRightward YES 则是右挥。
# 加 -enabled NO 可关掉摄像头，避免头姿切屏把光标移到另一块屏
open build/DerivedData/Build/Products/Debug/Lookpoint.app --args -enabled NO -debugSwipeAfter 3
```

### 签名（重要）

- 工程用 Apple Development 证书**手动签名**（`CODE_SIGN_STYLE = Manual`，Team `QGZ4G5UJ65`），Bundle ID 固定为 `io.github.wan-kai.lookpoint`。不要改成 ad-hoc 签名，否则每次重新构建后，系统的摄像头和辅助功能授权都可能失效。其他开发者构建时，把 `DEVELOPMENT_TEAM` 改成自己的。
- **App Sandbox 已关闭**：开了沙盒拿不到辅助功能权限，也发不了 `CGEvent`。Hardened Runtime 也是关闭的。以后要分发只能走 Developer ID + 公证，届时要打开 Hardened Runtime，并加上 `com.apple.security.device.camera` entitlement。

## 设计与参数

### 头姿切屏

| 机制 | 值 |
|---|---|
| 内建屏阈值 / 外接屏阈值，两者之间是保持当前屏的过渡区 | 8° / max(12°, 0.6 × 校准角)，未校准时为 15° |
| dwell：需要在新区域连续停留 | 300 ms |
| cooldown：两次切换的最小间隔 | 600 ms |
| grace：打字或用鼠标后暂停判定 | 1.5 s |
| One-Euro 滤波（yaw / pitch） | minCutoff 1 Hz，β 0.02 |

阈值在 `HeadPoseRouter.Config` 里，滤波参数在 `AppModel` 里。

### 手势

阈值都在 `GestureStateMachine.Config` 里。设计依据：2026-11-10 的 7.9 分钟真实录制，以及对 Vision Pro、Quest、Android XR、Apple Watch 和几个开源手势鼠标的调研。

- 识别用 Apple Vision：30 fps，单帧中位数 9.4 ms。放在键盘上的手完全拍不到，所以打字不会误触发。
- 拇指捏中指和拇指捏食指，在 Vision 下 77% 的帧分不开，所以没有用捏中指。
- 握拳时拇指也贴着食指。区分靠两条：无名指和小指的伸直比（握拳约 0.75，捏合约 1.05，阈值 0.88），以及捏合必须在张开手掌后 0.6 秒内开始。
- 主流 XR 产品用"捏住拖动"来滚动，但在 Mac 上这已经是左键拖拽，所以滚动改用双指。
- 左右切换和 swish 一样用 V 左右挥，对应触控板的三指横滑。张开手掌挥会和移动光标冲突，握拳挥会和离合冲突，所以都没用。
- 切换空间发的是 ⌃← / ⌃→。实测（macOS 26）：投递到 HID 事件层系统不认，必须投递到 session 事件层，并且按键之间要有约 20 ms 间隔，否则也不认。这串按键在后台队列里发，不阻塞主线程。
- 主流产品的快捷键是"翻手 + 捏"，但还没验证 Vision 能分清掌心和手背，所以先用"指向并保持"。保持期间手必须静止，边指边移动不会触发。
- 新的手形要连续 3 帧才生效；捏合要连续 2 帧，并且有迟滞（按下 0.25 / 抬起 0.40）。
- 手丢失 0.25 秒以内（快速移动时的拖影）不打断任何手势，包括拖拽；超过 0.25 秒才抬起左键，超过 0.5 秒才退出。
- 左右挥按"笔画"检测，用的是未经滤波的手掌位置（滤波会削弱速度）；收手的判断看位置，不看速度，因为挥手录制里收手的速度和出手差不多（0.5–0.8 对 0.64–1.0 画面高度/秒）。
- 没有用"按住 ⌘ 激活"，因为目标就是不碰键盘。
- 所有退出路径都会先抬起左键，不会让按键卡住。

```
                                需要时每帧跑手部；同一帧的请求共用一个 VNImageRequestHandler
  HeadPose/

    OneEuroFilter.swift
  Hand/
    HandLandmarks.swift         21 个关键点（MediaPipe 顺序，左上角为原点，归一化坐标）

  Gesture/

    GestureStateMachine.swift   手势状态机（纯 Swift）
    GestureOutput.swift         CGEvent：移动、点击、像素滚动、右 Alt、回车、⌃←/⌃→ 切换空间
  Screens/
    DisplaySwitcher.swift       CGDisplay* + CGWarpMouseCursorPosition
    UserActivityMonitor.swift   打字和鼠标活动的 grace 计时
  UI/                           控制面板、校准窗口、手部实验窗口
LookpointTests/                 Swift Testing：头姿路由、滤波、手势状态机（合成序列和真实录制回放），
                                重点覆盖"不应触发"的情况
  hand-recording-2026-11-10.json.deflate   日常手势录制片段，只有关键点，没有画面
  swipe-recording-2026-11-10.json.deflate  左右挥手录制（左 8 次、右 7 次）
```

整个 App 只有一个进程独占摄像头，同一帧同时供头姿和手部两路识别使用。

## 已知限制

- 只支持两块屏：主屏是内建屏（没有内建屏时用系统主屏），副屏是另一块激活且非镜像的屏。
- 未校准时，转向左右两边都算看外接屏。
- 头转得太偏（大约超过 45°）时可能检测不到脸，这时保持当前屏不变。
- 回车依赖程序自己记录的右 Alt 次数，键盘手动按过右 Alt 后可能对不上（见上文）。
